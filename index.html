01 — About

A book, not a manual. —— 这是一本书，不是手册

这本书不是用户手册，也不是 API 参考。它是对 Claude Code 仓库的一次深读 —— 只讲值得带走的工程做法：Agent Loop 怎么把九类横切关注点拼成一条可读主干；sub-agent 用什么机制共用父 session 的 token 预算；权限系统怎么做到"每次都问"却不烦；Skills、Plugins、MCP、Hooks 这几层扩展机制如何分工。

P · 01

One idea per chapter

每一章只挑一个值得借鉴的设计点讲透，5 页能讲完就 5 页，不追求覆盖度均衡。

P · 02

Cite or die

凡结论必附 path/file.ts:line 级别的源码引用。无引用的陈述视为无效。

P · 03

No marketing voice

禁用"优雅 / 精妙 / 惊艳"。只说为什么这样做，换一种会怎样，成本与收益。

P · 04

Engineer-to-engineer

读者假设是熟悉 TS / LLM / CLI 的工程师。不讲基础概念。

CH03 PARTII / Core Engine REFS47 · file:line READ32 min

Agent Loop 推理-工具循环主引擎

官方文档里是 5 行伪码。Claude Code 里是一个 1729 行的 async generator 加上 1295 行的包装类。中间那 3000 行处理的是"伪码没告诉你"的那些问题。

你在终端敲一条"把 src/utils/foo.ts 里的 memoize 换成 lodash/memoize"，按下回车。之后发生的事是一条流水线：模型先 yield 一段文本，再 yield 一个 tool_use，工具执行完把 tool_result 喂回模型，再 yield 下一个 tool_use，直到 end_turn。

屏幕上看到的这条"tool_use → tool_result → assistant → tool_use → …"，在 Anthropic 官方文档里是 5 行伪码；在 Claude Code 里共同处理伪码没告诉你的那些问题：流式工具执行、模型 fallback、上下文超限、输出被截断、stop hook 反复拦截、用户提前打断、权限请求等待。

Claude Code 把一条 agent 会话拆成两层 —— 外层 QueryEngine 是 session 级对象，每 conversation 一个，持有跨 turn 不变的东西；内层 query() 是一个纯 async generator，只管消息进、消息出，不接 UI 状态、不管 session 存储。

分层的意义在 query() 的复用性 —— 它既被 QueryEngine.submitMessage 调用（主线程），也被 sub-agent 调用（子 query 起一个嵌套循环，见 ch.04），也被 compact 子任务调用（见 ch.07）。分层因此不是可有可无。

query() 不该知道"美元"或"JSON schema 重试"这种应用层概念。它只负责把消息往外 yield，QueryEngine 在外面决定何时喊停。 § 3.4 · 错误预算的三条独立通道

submitMessage 里把错误预算拆成三个独立上限：轮数、美元预算、结构化输出重试次数。三者走同一条 result 通道但 subtype 不同，让 SDK consumer 能分类处理。这三个 check 本可以塞进 query() 里，放在外面的原因是 —— query() 不该知道"美元"这种应用层概念。
