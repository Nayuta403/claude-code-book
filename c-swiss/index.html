§ 00 · 提要

这本书不是用户手册，也不是 API 参考。它是对 Claude Code 仓库的一次深读 —— 只讲值得带走的工程做法：Agent Loop 怎么把九类横切关注点拼成一条可读主干；sub-agent 用什么机制共用父 session 的 token 预算；权限系统怎么做到"每次都问"却不烦；Skills、Plugins、MCP、Hooks 这几层扩展机制如何分工。

每一章只讲一个设计点。凡结论必附 path/file.ts:line 级别的源码引用。禁用空洞评价，只说为什么这样做、换一种会怎样、成本是什么、收益是什么。

chapter 03 · part iiAgent Loop：推理-工具循环主引擎

你在终端敲一条"把 src/utils/foo.ts 里的 memoize 换成 lodash/memoize"，按下回车。之后发生的事是一条流水线：模型先 yield 一段文本，再 yield 一个 tool_use，工具执行完把 tool_result 喂回模型，再 yield 下一个 tool_use，直到 end_turn。

屏幕上看到的这条"tool_use → tool_result → assistant → tool_use → …"，在 Anthropic 官方文档里是 5 行伪码；在 Claude Code 里是一个 1729 行的 async generator 加上 1295 行的包装类，共同处理伪码没告诉你的那些问题：流式工具执行、模型 fallback、上下文超限、输出被截断、stop hook 反复拦截、用户提前打断、权限请求等待。

Claude Code 把一条 agent 会话拆成两层 —— 外层 QueryEngine§3.1 是 session 级对象，每 conversation 一个，持有跨 turn 不变的东西；内层 query()§3.2 是一个纯 async generator，只管消息进、消息出，不接 UI 状态、不管 session 存储。

分层的意义在 query() 的复用性：它既被 QueryEngine.submitMessage 调用（主线程），也被 sub-agent 调用（子 query 起一个嵌套循环，见 § 04），也被 compact 子任务调用（见 § 07）。分层因此不是可有可无。

query() 不该知道"美元"或"JSON schema 重试"这种应用层概念。它只负责把消息往外 yield，QueryEngine 在外面决定何时喊停。 § 3.4 — 错误预算的三条独立通道
